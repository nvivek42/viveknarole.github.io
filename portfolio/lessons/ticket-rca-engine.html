The ticket that writes its own resolution

2025 · building · knowledge transfer · IT systems

Portfolio Lessons

Core Idea

Manual triage of IT slowness tickets is fragmented, repetitive, and forgetful. The solution isn't more documentation — it's a deterministic RCA engine that captures patterns, ranks by evidence, and prescribes safe, gated fixes.

Situation

Three years ago, I watched an L1 engineer manually correlate CPU spikes, DNS failures, and bloated roaming profiles for the fiftieth time that week. "There has to be a pattern," he said. There was. My background in UPSC preparation taught me to decompose any problem into atoms, rank by evidence, and conclude without flinch. That mental model became the spine of OfficeTicketingTool's RCA engine.

What I Built

OfficeTicketingTool is a WPF/.NET 8 desktop ticketing system with an embedded AI RCA engine. Twelve signal collectors — CPU, RAM, disk, AD, DNS, WiFi, VPN, Outlook, printers, licensing, peripherals — feed a deterministic rule chain: DNS/auth → DC overload → profile bloat → HDD+RAM bottleneck → disk health → space → WiFi → background processes → aging hardware → startup bloat. First rule that fires wins. Confidence from data completeness. No hallucination.

  • Engineering discipline: `net8.0-windows` TFM dropped 24 MB by ditching WinRT projections. OxyPlot replaced SkiaSharp — 33 MB vs 224 MB, zero native deps. EF Core's default `NoTracking` cut dashboard memory 40%. Workstation GC for single-user desktop. Tiered PGO for hot paths. Soft deletes everywhere. BCrypt with adaptive cost. Full audit trail. CERT-In/SEBI runbooks. India IT auditor dossiers ready day one.
  • Auto-fix policy-as-code: Executors (spooler restart, DNS flush, `klist purge`, temp cleanup) sit behind three gates: global kill-switch, `RiskTier.Low` only, curated allowlist. L1 gets startup cleanup. L2 gets GPO redirection. L3 gets WiFi channels. IT Manager gets hardware approvals. Escalation isn't failure — it's policy.

Knowledge Transfer

The six honest men — Who, What, When, Where, Why, How — didn't just frame this article. They framed the architecture.

  • Who — Systems engineer applying UPSC's analytical rigor (decompose → prioritize → evidence → conclude) to enterprise IT.
  • What — WPF/.NET 8 ticketing with embedded AI RCA engine, 12 collectors, 10 ordered rules, confidence-scored RCA, dual-audience remediation, gated auto-fix.
  • When — Iteratively hardened; now net8.0-windows with OxyPlot (zero native deps).
  • Where — On-premise AD: mixed LAN/WiFi, domain-joined endpoints, physical DCs.
  • Why — Manual slowness/hang triage burned L1 hours; escalations lacked evidence. Goal: machine-first diagnostics — auto-create tickets, run scoped collection, correlate incidents, generate remediation plans with rollback, escalate only when risk-tier/allowlist demands.
  • How — MVVM + DI + Repository + EF Core 8 + ML.NET. Knowledge transfer: UPSC's structured reasoning maps 1:1 to RCA rule ordering, confidence thresholds, escalation logic. Engineering gave: net8.0-windows (–24 MB), OxyPlot over SkiaSharp (33 MB vs 224 MB), `NoTracking` default (–40% memory), Workstation GC, tiered PGO.

Why It Matters

Most IT tools log tickets. This one diagnoses, prescribes, and safely executes. The shift is from reactive firefighting to proactive reliability. From tribal knowledge to executable logic. When a user reports slowness today, the ticket creates itself, diagnostics run scoped collection, incidents correlate, a remediation plan generates with rollback metadata, and the engineer reads an RCA summary — specific numbers, not generalities — and knows exactly what to do. Or the machine fixes it overnight and closes the ticket with evidence.

How to Apply

  • Audit your triage process: where are the repetitive manual walks? Those are candidates for deterministic rule chains.
  • Decompose your domain problems into atoms — not vague categories, but measurable signals with thresholds.
  • Rank rules by evidence, not convenience. The first rule that fires is your primary root cause.
  • Gate auto-fixes behind policy, not enthusiasm. Kill-switch + risk tier + allowlist = safety by design.
  • Document knowledge transfer explicitly. What from your past (psychology, engineering, exams, failed interviews) unexpectedly became valuable? That's Range — use it.
