Personal essay · Systems

The ticket that kept coming back

nonlinear careers · generalism · persistence · IT systems

Every IT team has a version of this. Slowness reported. Engineer opens a ticket. Checks CPU. Checks RAM. Closes it. Two weeks later — same machine, same complaint, different engineer, same manual walk-through. No record of what was tried. No memory between tickets.

Someone eventually has to get tired enough to build the thing that should have existed already. The person with an odd mix of backgrounds — engineering, psychology, years studying how systems and people break down — turned out to be exactly the one needed.

  • Engineering: structured thinking → deterministic RCA chain.
  • UPSC · Psychology: multiperspective reasoning → UX decisions a pure dev wouldn't make.
  • Failed interviews: narrow became wide → finally understood the full IT landscape.
  • All of it: persistence without proof → shipped anyway. Iterated until it worked.
