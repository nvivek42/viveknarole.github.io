My story

After each failed attempt I went back, worked out what I was missing and rebuilt my method. What I’ve built

IT support diagnostics

Ticketing and automated root-cause analysis

IT support depended on engineers diagnosing each problem from memory and typing fixes by hand, machine by machine. I built a ticketing system with a diagnostic engine. It reads signals from the user’s PC, works out the likely root cause, and fixes the low-risk problems by itself, behind safety checks and with the ability to undo.

In use today.

How it works and what it’s built with
  • Twelve collectors read signals from the PC: processor, memory, disk, network, printers, sign-in, Outlook, VPN, display, licensing and peripherals.
  • A rule engine turns those signals into findings across 28+ root-cause categories, each with a confidence score. The rules live in an editable file, so the logic can change without rewriting the software.
  • Seven low-risk fixes, such as restarting the print spooler or flushing the DNS cache, run on their own only when three checks pass: a master switch is on, the fix is low risk, and it is on an approved list. The previous state is saved so a failed fix can be rolled back.
  • End users get plain-English steps. IT agents get the technical detail and commands.
  • Includes the ticket lifecycle, SLA tracking, role-based access, an audit trail and reporting. The installer was cut from about 224 MB to about 33 MB.
  • I built it with AI coding agents. I made the design decisions, including the safety rules, and reviewed the output.

C#, .NET 8, WPF, Entity Framework Core, MySQL, YAML rules, MSIX packaging

Inventory valuation

Month-end accounting automation for a manufacturer

A manufacturer valued its inventory across about 184 products using spreadsheets and a long manual checklist. I built a pipeline that calculates the valuation to the international inventory standard (IAS 2) and produces an audit-ready Excel file. A finance team member can trace any number back to its source.

In use today.

How it works and what it’s built with
  • For every product it calculates production cost, landed cost and net realisable value, then applies the lower-of-cost-or-NRV rule to work in progress, finished goods and goods in transit.
  • The cost build-up covers raw material rates averaged from the purchase ledger, bills of materials, wastage and rejection allowances, melting loss, seven overhead pools split by quantity, weight and net output, plus subcontract, freight and commission costs.
  • Money is calculated with exact decimal arithmetic instead of floating-point numbers. The Excel output keeps the original column letters, so auditors can compare it with the old workbook.
  • A formula-by-formula guide maps every calculation to its source data and code, so someone other than me can maintain it.
  • It has a desktop interface because the web version could not be installed on the finance team’s machines.
  • I built it with AI coding agents. I set the rules and checked the results.

Python, MySQL, openpyxl, Streamlit, Tkinter
